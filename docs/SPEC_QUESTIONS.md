# Shalimar Specification Questions and Conformance Decisions

This file records questions that must be resolved before claiming complete Shalimar 3.0 conformance. It is not permission to silently alter the language reference.

| Topic | Current compiler evidence | Required decision / action | Status |
|---|---|---|---|
| Integer overflow | AST-to-C and IR-native now guard scalar integer `+`, `-`, `*`, `/`, `%`, unary negation, and scalar integer `+:`/`-:` compound assignments. Checks use a wider intermediate for add/subtract/multiply and explicitly reject `INT32_MIN / -1` and `INT32_MIN % -1`. | Extend the audit to every generated integer path, especially loop induction updates, array dimension arithmetic, and optimizer rewrites; freeze the exact overflow policy in the language reference. | Partially implemented; audit remains open |
| Division and remainder by zero | Both backends now guard scalar integer `/` and `%` expressions, including divide/remainder by zero and the `INT32_MIN / -1` overflow case. Regression tests exercise each failure in both backends. | Verify all remaining paths and decide/document real division-by-zero and non-finite real behavior. | Partially implemented; real semantics open |
| `int(real)` range | Both backends check finiteness and the truncated value against the signed 32-bit range before conversion. Tests cover out-of-range finite input and non-finite input produced by power. | Add endpoint tests and review every cast path, including conversions nested in global initialization and any future backend. | Partially implemented; endpoint audit open |
| `char(value)` range | Both backends now reject non-finite values and truncated values outside 0..255 before conversion. Tests cover 256 and -1. | Confirm the 0..255 rule against the frozen language specification and test endpoints 0 and 255 in all paths. | Partially implemented; endpoint audit open |
| Real non-finite behavior | `pow`, division, and other real operations use the C math runtime. Full language-defined handling of non-finite results is not verified. | Specify and test the intended runtime diagnostics or accepted values. | Open |
| String escape sequences | The canonical reference states that string literals do not interpret escape sequences. | Preserve this behavior and ensure both backends treat literal contents identically. | Confirmed rule; broader tests needed |
| Array-rank parity | AST-to-C supports a broader set of ranks and runtime local arrays than IR-native, which is limited to supported rank-one/rank-two integer arrays and rank-one strings. | Keep AST behavior as the reference; add missing IR support or explicit diagnostics and matrix entries. | Open |
| Cross-file `uses` | The current compiler resolves a limited borrowed built-in set within one source file; it does not implement general cross-file imports. | Document as a compiler limitation unless a module/import design is approved. | Open |
| Multi-output functions | The AST backend supports multi-output functions; IR-native currently supports only zero or one output. | Implement multi-output IR lowering/codegen or retain a precise diagnostic in that backend. | Open |
| Debug variable mapping | Source `#line` mappings exist, but variable and expression-level mapping depends on the host compiler and is incomplete. | Test and document the actual debugger capabilities for each native toolchain. | Open |
